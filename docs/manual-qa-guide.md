# Сквозная локальная проверка

Ветка `local/e2e` соединяет полный backend из `origin/artur` и интерфейс из
`zakhar`. В ней исправлены соединения записи с обработкой, приглашения,
уточнения, восстановление сессии и пересчёт результатов после ревью.
Исходная ветка `zakhar` и прежняя база на порту 5433 сохранены.

## Вход и сценарий рекрутера

Открыть http://localhost:5173/staff/vacancies. Выбрать «Рекрутер», ввести любое
имя (например `artur`), пароль — `INTERNAL_AUTH_PASSWORD` из `.env`,
по умолчанию `change-me`. Это локальная схема входа для проверки ролей.

1. Можно использовать готовую вакансию «E2E — Python developer»: два топика,
   обязательный hard «Python async» и желательный soft «Командная работа».
   Для собственной вакансии нажать «Создать вакансию», заполнить требования.
   Форму можно заполнить из PDF-описания: приложить файл в блоке «Описание вакансии
   в PDF», дождаться разбора и поправить топики руками. Блок «Примеры вопросов» —
   ориентир для генерации, его тоже стоит заполнить.
2. Нажать «Вопросы» на странице вакансий и «Сгенерировать недостающие».
   Повторный вызов использует сохранённое ядро.
3. Через «Сменить роль» войти как «Техспециалист», на той же странице поправить
   формулировки и нажать «Подтвердить список». Правка после подтверждения
   возвращает вопрос в черновик — список нужно подтвердить заново.
4. Вернуться рекрутером, нажать «Кандидаты», при желании вставить тестовое резюме
   и нажать «Пригласить кандидата». Без подтверждённого списка вопросов приглашение
   не создаётся. С резюме кандидат получит вопросы, раскрытые под его опыт.
5. Ссылка копируется в буфер сразу при создании приглашения и по кнопке «Ссылка».
   Для каждого нового прохождения создавать нового кандидата: ответы нельзя
   перезаписывать.

## Сценарий кандидата

1. Открыть персональную ссылку, желательно в отдельном окне/инкогнито.
2. Дать согласие на запись и обработку, разрешить камеру и микрофон.
3. Нажать «Записать 3 секунды», посмотреть и прослушать пробу. Затем нажать
   «Меня видно и слышно — начать интервью».
4. Дождаться окончания озвучки: после неё запись начинается автоматически.
   На основной ответ максимум 2 минуты, на уточнение — 1 минута.
   Можно закончить раньше кнопкой «Закончить ответ».
5. Дождаться подтверждения сохранения и решения об уточнении. Сначала идёт
   распознавание ответа, затем быстрый вызов модели с бюджетом
   `FOLLOWUP_DECISION_TIMEOUT_SECONDS` (по умолчанию 20 секунд).
   Если распознавание/уточнение недоступно, прохождение продолжится; такой
   сбой не должен автоматически превращаться в профессиональный отказ.
6. Перейти к следующему вопросу. Для проверки отрицательного сценария можно
   осознанно пропустить один вопрос. Пропуск фиксируется как «не подтверждено».
7. Нажать «Завершить и отправить интервью». После экрана «Интервью отправлено»
   ссылка перестаёт действовать. Готовность оценки смотреть в кабинете команды.

Для проверки восстановления обновить страницу между сохранёнными ответами:
интервью должно открыться на первом неотвеченном вопросе. Если вкладка закрылась
во время записи, сохранённые чанки не означают завершённый ответ; не считать
такой тест успешным без сообщения о сохранении.

## Результаты и экспертная проверка

1. В кабинете рекрутера открыть «Кандидаты». Список обновляется каждые 5 секунд.
   Дождаться `processed` и «Готово». Обычно это десятки секунд после отправки,
   но время зависит от провайдеров и длины ответов.
2. Открыть кандидата: проверить матрицу, рекомендацию по правилам и Coverage.
   Нажать статус с пометкой «цитата и видео», воспроизвести фрагмент.
3. Открыть полный транскрипт: проверить текст, таймкоды и запись каждого ответа.
   Запись доступна и для ответа, из которого система не смогла выделить evidence.
4. Через «Сменить роль» войти как «Техспециалист» с любым именем и тем же
   локальным паролем. В «Ревью» доступны спорные hard-топики. Выбрать топик,
   посмотреть запись, указать новый статус и обязательный комментарий.
5. Повторить как «Нанимающий менеджер» для soft-топиков. Рекрутер не меняет
   статусы; техспециалист не меняет soft, менеджер не меняет hard.
6. Проверить обновлённую карточку и «Метрики». `system_status` должен остаться
   прежним, `current_status` отражает правку; изменение записывается в историю.
7. В карточке открыть «Ссылки и журнал просмотров»: проверить аудит видео,
   создать ссылку результата, открыть под внутренней ролью, затем отозвать.

Если ответ подробный и все топики определены уверенно, очередь ревью может быть
пустой — это ожидаемо. Для проверки очереди дать общий ответ без конкретного
примера. Экспертные решения при тестировании остаются решениями человека.

## Управление запуском

Из корня проекта:

```bash
bash scripts/local.sh start
bash scripts/local.sh status
bash scripts/local.sh stop
```

`start` поднимает отдельные Docker volumes, применяет миграции, проверяет бакет,
собирает интерфейс и запускает API, Celery worker, Celery beat и frontend через
пользовательские службы systemd с автоматическим перезапуском при падении.
Закрытие терминала не останавливает их. После перезагрузки компьютера или выхода
из пользовательской сессии выполнить `start` снова. При переключении ветки
сначала остановить службы, иначе процессы будут работать с другой версией кода.

```bash
journalctl --user -u interviewer-api -u interviewer-worker -u interviewer-beat -f
```

API: http://localhost:8000/docs. Проверка БД: http://localhost:8000/health/db.
MinIO: http://localhost:9001 (доступ из `S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY`).
PostgreSQL — 5434, Redis — 6380, S3 — 9000. Все новые порты привязаны к loopback.
Секреты остаются в `.env`; `.env.local` содержит настройки локальной инфраструктуры.
Не выполнять `docker compose down -v`, если нужно сохранить интервью.

## Автоматические проверки

```bash
uv run ruff check .
uv run pytest -q
npm --prefix frontend run build
cd frontend
NODE_OPTIONS=--experimental-global-webcrypto npm test
```

Провайдеры используются реальные: LLM из `OPENAI_BASE_URL`, голос из
`AUDIO_BASE_URL`. Генерация, озвучка, распознавание и оценка расходуют квоту ключей.
Тестовые браузерные прогоны используют синтетические камеру и речь, а не ваши ПДн.
