# CLAUDE.md — правила разработки

> Общие правила для кодовых ассистентов (Claude Code и Codex) и людей в команде.
> Codex читает копию этих правил в `AGENTS.md` — **держи оба файла в синхроне**.

## Что за система

Веб-платформа **асинхронного видеоинтервью** для первичной технической оценки
ИТ-кандидатов. Кандидат по персональной ссылке в удобное время проходит интервью
с камерой и микрофоном: система показывает и озвучивает вопросы, записывает ответы,
транскрибирует их и формирует **карту покрытия требований вакансии**.

Единица оценки — не балл кандидата, а **покрытие требований**. По каждому топику
система выдаёт один из статусов (✅ подтверждено / ❓ требует проверки / ❌ не
подтверждено) с обязательным **evidence** — цитатой из транскрипта и таймкодом видео.

Полный контекст — в `data/PRD-AI-Interviewer-2026-09-04.md`. План работ — в `tasks.json`.

## Продуктовые инварианты (НЕ нарушать)

Это не стилистика, а суть продукта — код, ломающий любой из пунктов, неверен:

1. **Финальное кадровое решение принимает человек.** LLM не выносит вердикт.
2. **AI-score не выводится нигде** — ни в UI, ни в API. Только тройка статусов и дробь Coverage.
3. **Итоговая рекомендация детерминирована** — чистая функция от матрицы топиков, не суждение LLM.
4. **`system_status` никогда не перезаписывается.** Правки эксперта идут в `current_status` + append-only лог. Метрика 80% меряется по `system_status`.
5. **Изоляция топиков:** оценивается только требование того топика, к которому задан вопрос. Упоминания чужих технологий игнорируются.
6. **«Требует проверки» — состояние по умолчанию.** Автоотказ только при явном стоп-факторе с высокой уверенностью.
7. **RBAC:** рекрутер настраивает всё, но не меняет статусы. Hard-топики — техспециалист, soft — нанимающий менеджер.
8. **152-ФЗ:** все персональные данные (видео, аудио, резюме) хранятся в РФ. Никаких зарубежных облаков и LLM API.

## Стек

| Слой | Технология |
|---|---|
| Backend | Python 3.12+, FastAPI, Pydantic v2 |
| Пакеты/venv | **uv** (`.venv`), зависимости в `pyproject.toml` |
| БД | PostgreSQL + SQLAlchemy 2.x + Alembic |

| Хранилище | S3-совместимое (Yandex Object Storage; dev — MinIO) |

| Frontend | React + TypeScript + Vite, MediaRecorder API |
| Auth | JWT (внутренние роли) + магические ссылки (кандидаты) |

## Правила кода

**Python**
- Зависимости и запуск только через `uv` (`uv add`, `uv run ...`). Не редактировать `.venv` руками.
- Линт и формат — `ruff` (`uv run ruff check .`, `uv run ruff format .`). Типы — аннотировать везде, проверять `mypy`.
- Тесты — `pytest` (`uv run pytest`). У каждой фичи — тест.
- Async для I/O (БД, HTTP, S3). CPU/блокирующее — в Celery-воркеры.
- **Детерминированная логика (`services/`) отделена от `integrations/`** и тестируется без сети. Внешние сервисы (LLM/ASR/TTS/S3) — за интерфейсами, чтобы провайдер менялся без правок бизнес-логики.
- Версионируй воспроизводимость: `vacancy_version`, `model_version`, `prompt_version` пишутся в результат. Промпты — в `prompts/`, версионируются.

**Frontend**
- TypeScript strict, функциональные компоненты, хуки. Запись — через `MediaRecorder`, загрузка чанками (без WebRTC).

**Секреты и данные**
- Секреты только из окружения / `.env`. Никогда не хардкодить и не коммитить (`.env` в `.gitignore`; шаблон — `.env.example`).
- Не коммитить ПДн и датасеты из `data/` (кроме PRD).

**Git**
- Маленькие атомарные коммиты, одна фича — один коммит. Ветки от `main`.

## Рабочий процесс (tasks.json + ralph.sh)

Разработка идёт **по одной задаче за сессию** из `tasks.json`:
1. Прочитать `tasks.json` и `git log --oneline -20`. Выбрать ОДНУ `pending`-задачу с наивысшим приоритетом.
2. Убедиться, что все её `dependencies` в статусе `done`. Если нет — взять другую.
3. Работать только над ней. Прогнать `uv run ruff check .` и `uv run pytest`.
4. Выполнить ВСЕ `test_steps`. Перевести `status` в `done` **только** после их прохождения.
5. Дописать краткий итог в `progress.md`, сделать git commit.
6. **Запрещено удалять или редактировать задачи — можно менять только `status`.**

Автоматический прогон: `./ralph.sh <кол-во> <claude|codex>` — например `./ralph.sh 5 codex`
выполнит 5 задач через Codex. `./ralph.sh` без аргументов — все оставшиеся.
